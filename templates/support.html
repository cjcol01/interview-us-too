Chrome blocks microphone access per-site until you grant it, and once you deny it, Chrome won't prompt again — it just fails silently from then on. It can also happen if your OS has the wrong input device selected, muted, or if another app is holding the mic exclusively.

  1. Open chrome://settings/content/microphone and make sure this site isn't listed under "Not allowed".
  2. Click the padlock icon in the address bar → Site settings → set Microphone to "Allow", then reload the dashboard tab.
  3. Check System Settings → Sound and confirm the right input device is selected and isn't muted.
  4. Close other apps that might be using the mic exclusively (Zoom, Teams, OBS), then try the hotkey again.
  5. Run the system check above — the Microphone row turns green once permission is granted.
Note: Chrome never re-prompts after a denial — you have to clear the block manually in site settings.

Instant replay only buffers audio from a tab you've explicitly locked in the extension popup. If nothing is locked, or the locked tab was closed or refreshed, there's no buffer for the hotkey to pull from. Check its still locked and wait up to 30 seconds.

  1. Open the extension popup and lock it to your interview tab.
  2. Leave that tab open and playing audio for a few seconds before pressing replay — the buffer needs time to fill.
  3. If the dashboard badge shows "replay lost" or "replay error", click re-lock without leaving the page.
  4. Refreshing or closing the locked tab clears the buffer — re-lock a tab if that happens mid-interview.
Note: the buffer only ever holds your configured window — adjust it under Settings → Capture & replay.

Managed or work Chrome profiles often block installs that aren't on an approved list, and Chrome frequently hides a newly installed extension behind the puzzle-piece icon instead of pinning it to the toolbar.

  1. Confirm you're using Chrome or another Chromium browser — Safari and Firefox aren't supported (yet).
  2. Click the puzzle-piece icon in the toolbar and pin InterviewAce so it's always visible.
  3. If a work laptop blocks the install, try a personal Chrome profile, or use the manual install instead.

This means the extension's content script never injected into this tab at all, so there's nothing to talk to — different from "not connected", where it responds but has no stored account link. It's usually a permission or install-source issue rather than anything about your account.

  1. Open chrome://extensions and confirm InterviewAce is toggled on, not just installed.
  2. Click "Details" on the extension and check "Site access" — set it to "On all sites". Sideloaded/unpacked installs sometimes default to something more restricted.
  3. If you're in an Incognito or Guest window, extensions don't run there unless "Allow in Incognito" is switched on for it.
  4. Do a full reload of the tab (not just re-running the check) — permission changes only apply to newly loaded tabs.
  5. Run the system check above again.
Note: if you maintain your own build of the extension, double-check you're loading the folder you think you are — Chrome will happily keep running a stale copy from a different location.

Your phone isn't paired separately — it's just the same dashboard, signed into the same account, open in a mobile browser. If the phone is signed out, backgrounded, or loses network, it stops receiving the live stream.

  1. On your phone, open the same dashboard URL and confirm you're signed into the same account.
  2. Keep the phone's browser tab in the foreground — backgrounding it can pause the live connection.
  3. Re-scan the QR code from onboarding, or open the dashboard link again, if the session looks stale.
  4. Check your phone has a stable connection — try mobile data if Wi-Fi is flaky.

Some apps — DRM-protected video, certain native windows — render as black in any screen capture even though you can see them fine yourself. Sharing the wrong tab, or one that hasn't finished loading, produces the same result.

  1. Make sure you're sharing the tab or window that actually has the question on it, not a blank new tab.
  2. Stop the current capture and re-select the correct tab, window, or screen.
  3. If the source is DRM-protected content, it may never capture correctly — describe or paste the question instead.
  4. Give the page a second to finish rendering before pressing the capture hotkey.

The extension only listens for hotkeys on pages where its content script has already loaded, and a custom key combo can silently collide with a shortcut the browser or OS already owns.

  1. Refresh the page after installing or updating the extension — content scripts don't inject into tabs that were already open.
  2. Check Settings → Shortcuts for the exact combo currently set, and try re-recording it in case of a conflict.
  3. Avoid combos your browser or OS already owns.
  4. Confirm the extension is toggled on — press the toggle hotkey or check the popup.

Answers stream to your dashboard over a live connection; a flaky network, a backgrounded/throttled tab, or a temporary AI provider slowdown can each interrupt or delay it.

  1. Check your own network connection first — the stream reconnects automatically but needs a stable link.
  2. Keep the dashboard tab in the foreground; background throttling in some browsers can pause the connection.
  3. Give it a few seconds — the system automatically fails over to a backup AI provider if the primary is slow or down.
  4. Still stuck after ~15 seconds? Refresh the dashboard tab — your session and history carry over.
